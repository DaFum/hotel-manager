## Why a remediation plan is required

The audit found these concrete implementation gaps:

1. `GameCommand` is only a payload union in `GameSimulation.ts`; it lacks command ID,
   game time, actor, and optional expected state version. `commands.ts` merely re-exports
   that type. There is no persisted command log.
2. Successful commands do not emit domain events. The Worker defines
   `DOMAIN_EVENTS`/`PERF_SAMPLE` but does not publish them; `COMMAND_ACCEPTED` means
   queued, not applied. `STATE_DELTA` carries a full snapshot and `REQUEST_DETAILS`
   returns the full snapshot.
3. The simulation class imports nearly every subsystem and owns command definitions,
   validation, orchestration, and many rules. Rejected/transactional behavior is not
   protected by a general atomic command boundary or expected-state check.
4. Saves use one hard-coded UI slot. Monthly/yearly/pre-action autosaves, rotating
   recovery generations, validated Worker load envelopes, and recovery UI are absent.
5. Booking records do not retain the complete slice context needed for deterministic
   inventory and explanation; cancellation/no-show and room inventory are leaf
   transitions rather than one atomic reservation lifecycle.
6. Plan 02 calls F&B “full,” but integrated contracts for opening hours,
   reservations/waitlists, board plans, mise-en-place, allergies, waste, and several
   resource dependencies are missing. Utilities are not an authoritative operating
   system.
7. The isometric renderer is a static colored tile grid. MASTER camera/floor/focus,
   navigation, elevator/stair/queue visualization, day/night, LOD, and stable interaction
   targets are not implemented.
8. Plan 03's primary ten-year acceptance asserts only competitor count and supply.
   Supporting tests add one-seed bounds, direct-repeat equality, short real-simulation
   integration, and v2 migration smoke coverage, but do not prove shared-economics
   equivalence, multi-seed calibration, entry/exit scenarios, ordered event replay, or a
   mid-decade save/restore continuation.
9. The benchmark runs the real simulation, but there is no replay corpus with commands,
   ordered events, RNG checkpoints, and state hashes.

## Scope guard

and green. Reuse existing modules and content.

**Out of scope:** technology diffusion, post-1991 standards/platforms, multi-hotel
company systems, brands, narrative campaigns, content editor, final localization/audio,
and final mature-campaign optimization. Later channel types and corporate depth remain in
their owning future plans.

## Exit criteria

Plans 01-03 are “perfect” for their declared scope only when:

1. every claimed MASTER architecture invariant has executable evidence;
2. current leaf tests remain green and the new causal/system tests pass;
3. same state + commands + RNG produces identical state and ordered events across direct,
   replayed, and save/restored execution;
4. Worker acknowledgements, events, deltas, details, saves, and errors are truthful;
5. Plan 02 depth is integrated through shared resources and visible in Pixi plus DOM;
6. Plan 03 competitors remain economically fair and bounded over deterministic decades;
7. save v1-v4 migration and recovery preserve all authoritative state; and
8. the browser journey proves player-visible operation rather than nominal components.
